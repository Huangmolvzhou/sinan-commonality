# 司南 SINAN

**SMT 不良共性分析工具** —— 选一个项目、一段时间、一道工站、一个不良点位，工具自己去 MES 把机台、吸嘴、飞达、载具、钢网、材料批次，连同 SPI 与 AOI 的实测值全部拉出来，和同批正常板做对照，最后告诉你：**这批不良到底集中在哪一环。**

> 它不是"再做一个看板"。它要回答的是 PE/EE 每天真正卡住的那个问题 —— 十几个维度摆在面前，哪个是真的，哪个只是"看着高"。

## 它解决什么问题

一个典型场景：Post AOI 某个点位两天出了 31 条偏位不良。人工要做的是：

1. 把这 31 块板的 PanelCode 捞出来
2. 逐一去查它们过了哪台机、哪个穴位、哪把吸嘴、哪个飞达、哪批材料、哪块载具、哪块钢网
3. 再算每个取值"本来该占多少"（分母），才知道某个穴位是不是真的异常
4. 十几个维度 × 几十个取值，光算就有几百个"候选信号"，其中必然有十几个是巧合

第 3 步是绝大多数人跳过的，第 4 步是几乎所有人都栽过的。

**工具把 1–3 步变成 15 秒，把第 4 步变成一条统计学守卫。**

---

## 核心方法（三层）

### 第一层：分母 + 风险比

单看"某个穴位出了 14 条不良"没有意义 —— 要先问它一共被贴过多少次。

```
风险比 lift = (该取值占不良的份额) ÷ (该取值占全部暴露的份额)
```

实测案例：某穴位承担 14/300 条不良（4.67%），但它只占全部 23,468 次贴装的 84 次（0.36%）。
`4.67% ÷ 0.36% = 13.0 倍` —— 而且它等价于"不良率之比"：`16.7% ÷ 1.28% = 13.0 倍`。

> 注意 `14 ÷ 23,468 = 0.06%` 是**没有意义**的算法 —— 那个分母把别的穴位的贴装也摊进来了。**14 是分子，84 才是 0.36% 的分子。**

### 第二层：多重比较校正

看得越多，假信号越多。13 个维度、几十个取值等于几百次检验，按 95% 置信必出十几个"看起来显著"的。

工具内置 **二项上尾检验 + Holm 跨维度校正**（家族 = 全部维度全部候选，实测 259 个候选）。校正完了宁可报「分散」，也不硬指一个假的。

### 第三层：被动共现分离

同一个物理原因会让好几个维度同时"看起来集中"。例如载具某个穴位卡了异物 → 那个穴位不良升高、贴那个位置的吸嘴不良也升高、同批材料不良也升高 —— 但**吸嘴和材料本身没问题**。

`lib/v2/passive.js` 用「剔除后重算」把这类连带信号识别出来：

- **剔除要连暴露一起减**（不能只减不良，否则分母不变，算出来必然还是高）
- **必须不对称才判被动**（A 能解释 B、B 也能解释 A → 这是环，不能判）

被动的降级显示，不让它冒充真凶。

## 快速开始

```bash
# 1. 装依赖（只有一个：mssql）
npm install

# 2. 配数据库连接（三选一，优先级从高到低）
#    a) 环境变量
export MES_SQL_HOST=... MES_SQL_PORT=1433 MES_SQL_DATABASE=... \
       MES_SQL_USER=... MES_SQL_PASSWORD=...
#    b) 本机私有配置（推荐）
#       ~/.config/sinan/mes.local.json
#    c) 仓库内 config/mes.local.json（已被 .gitignore 排除）

# 3. 起服务
npm start          # 默认 http://127.0.0.1:8519

# 4. 跑离线回归测试（13 套 / 312 条断言，约 2 秒）
npm test
```

配置文件格式：

```json
{ "host": "你的主机", "port": 1433, "database": "mes40", "user": "只读账号", "password": "..." }
```

后段（成品测试段）另配一份 `be.local.json`，同样格式。

另外两个**可选**配置（不填不影响主流程）：

| 文件 | 用途 | 不填的后果 |
|---|---|---|
| `ch.local.json` | ClickHouse 地址 `{"url": "http://<host>:8123/"}`，用于「指标区分度（NG vs OK）」与 AOI/SPI 测量值对照 | 这两块标成「不可用」，共性分析、BE 段、SN 追溯全都不受影响 |
| `contact.local.json` | 作者邮箱/电话 `{"mail": "…", "tel": "…"}`，右上角「意见反馈」按钮用 | 按钮里显示「这一份没有预置维护者联系方式」，其余照常 |

也可以用环境变量 `SINAN_CH_URL` / `SINAN_CONTACT_MAIL` / `SINAN_CONTACT_TEL` 覆盖。
仓库里只有 `*.example.json` 示例，真实配置是 `*.local.json`，已被 `.gitignore` 挡住。

> 为什么这两样要外置：开源仓库里不该出现内网地址，更不该出现个人手机号。
> 代码只保留「读配置」的能力，具体值留在使用者的机器上。

    passive.js            ★ 被动共现分离

    link.js               前后段联动（BE 不良板 → SMT 面板反查）

前端是**纯手写 SVG**：小提琴图用 KDE（Silverman 带宽），箱线用 1.5 IQR，点按密度抖动铺开，刻度走 1/2/2.5/5/10 的 nice 数。没有 ECharts、没有 D3、没有构建步骤。

## 出来的结论长什么样

四档判定，从强到弱：

| 判定 | 含义 |
|---|---|
| **高度怀疑** | 通过显著性检验，且剔除被动信号后仍站得住 |
| **疑似传导** | 通过检验，但能被子集信号完全解释 → 降级 |
| **分散** | 没有维度通过门槛。**这也是一种结论** —— 说明该换角度查，不是没答案 |
| **样本不足** | 不良数太少（< 3）或暴露太小（< 5），明说看不出来，不硬凑 |

每次分析会附：

- **结论卡**：一句话说清指向哪一环，带风险比与置信度
- **泳道图**：一眼看共性集中在哪个维度（显著项标红）
- **Pareto**：先解决哪几个最划算（按**超额不良**排序，不是原始不良数）
- **每个候选的四格排查清单**：查什么 / 怎么查 / 判据 / 为什么查这些
- **指标区分度**：NG 与 OK 在 OffsetX/Y、Rotation、Lift、Height 上分得开不开（实测：Rotation 89% 的 NG 落在 OK 的 P1–P99 之外，OffsetX 0% → 「转歪了不是移歪了」）
- **慢性还是突发**：和过去 30 天逐日对比，说清这一窗是变差了还是本来就差

## 硬约束（设计上的取舍）

这些都是明确的、有理由的限制，不是没做完：

| 约束 | 值 | 为什么 |
|---|---|---|
| 只读 | 代码层 SELECT 白名单 | 生产库只碰得到读。字符串字面量先剥离再校验，避免 `'update'` 这类被误杀 |
| 时间窗 | ≤ 31 天 | 再宽会退化成全表扫，对 MES 不礼貌 |
| 单次分析上限 | 1,000 条不良 | 到 1,000 时端到端约 21 秒；再往上板数×贴装行齐涨，逼近 40 秒 |
| 并发 | 本机 4 条语句 / 2 个任务 | 压测过：5 人并发出 166 秒、8 人出 `ECONNRESET`。限流是为了别人能用 |
| 对照板 | 120 块 / 1,500 块 | 取数时间与代表性的折中，超了会明确提示"对照不足"，不静默降级 |

## 已知边界（如实交代）

1. **数据保留期**：AOI 主表只保留约 25～36 天，维修表留多年。窗口早于保留期时，工具会**直接提示**并给一键改日期的按钮，而不是返回空表让你猜。
2. **BE 段没有载具维度**：后段库的 `FixtureCode` / `SteelCode` 实测 100% 为 NULL，源数据就没有。只能靠过站编码里的工位/穴位/轨道。
3. **BE 过站编码约 37% 解析不出**：`ZD<机台>VSWR0004-01R` 这种格式能解，其它变体还在补。
4. **后段测试值取不到**：`T_Bllb_TestDefectInformation` 只有 pass/fail，完整测试数据存在 SMB 共享路径下，未接入。工具会如实标注，不假装有。
5. **实测值只有部分项目覆盖**：ClickHouse 侧覆盖部分产品，没覆盖的会明确提示"该项目无量测数据"。
6. **`public/aoi-tool.html`**（1.7 MB）是附带的独立单文件工具，**不是本仓库的原创代码**，来源与许可证待确认，因此**不随本仓库发布**（已在 `.gitignore` 里排除）。它只在本地发行包里存在，前端启动时会 HEAD 探一下：文件在就显示顶栏入口，不在就隐藏，不会点到 404。

## 安全

- 仓库内**不含任何凭据**。`.gitignore` 挡住 `*.local.json`、`config/mes.local.json`、`config/be.local.json`。
- 仓库内**不含客户信息**：客户回复口径文档、含客户方人员姓名的 MIL 相关文档、含真实产品名与机台名的迭代截图，均已排除。
- **不含内网主机地址**：MES / BE / ClickHouse 三个地址全部走配置（`lib/config.js`），源码与示例文件里只有 `<MES_HOST>` 这类占位符。
- **不含个人可识别信息**：作者邮箱与电话移到了 `contact.local.json` / 环境变量，源码里没有。
- **不含真实产线标识**：机台名、产品料号、面板码、SN、飞达/吸嘴号、工位码，在代码注释、测试数据、文档里统一换成了 `LINE-A` / `PRODUCT-A-001` / `PANEL00001` / `SN00000001` 这类代号。
- 报告与日志不回显密码或完整连接串。

审查方式：`node scripts/audit-sensitive.js`（零依赖，只扫 `git ls-files` 里的文件），应当全部为 0。
