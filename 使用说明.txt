════════ v6.7 干三件事 ════════

一、不良上限 300 → 1000（你问的「1000 有问题么」—— 实测没问题）
  原来卡 300 不是因为统计不吃，是因为「贴装明细」那条查询分批太粗：
  800 块板装一批、一批一批串着等。实测 795 块板要 77 秒，所以只能卡 300。
  v6.7 把分批改成 30 块一批、6 批并发，同一批数据 77,109ms → 3,438ms（快 22 倍）。
  拉高后的实测（PRODUCT-A-004 / COMP-B / 2026-10-19~25，总体 1,183 条）：
    · 1000 条不良 → 795 块板 / 50,790 次贴装 → 端到端约 21 秒
    · 300 条同样条件 → 端到端约 11 秒
  所以 1000 是跑得动的，不是硬拉。上限到底能到多少：再往上主要是「板数×贴装行数」
  一起涨，单次分析会逼近 40 秒以上，对 MES 也不礼貌，所以停在 1000。
  ★ 口径没变：超过 1000 时仍按不良 ID 的 MD5 稳定哈希抽 1000 条，
    页面和报告顶部会写明「总体 N 条 / 分析 1000 条 / 占比 P%」，
    同一份数据重跑永远抽到同一批，报告可以复核。

二、「工作台粘贴识别」默认折叠（你的原话：给个折叠选项，默认折叠，有需要再打开）
  它平时用不到，摊开却占掉筛选区一整行（文本框 + 按钮 + 提示），
  把天天用的「项目 / 日期 / 工站」挤到下面去了。现在收成一行标题：
  点那一行才展开，再点收起；折叠状态会记住，下次打开还是上次的样子。
  例外：从工作台点「查共性」跳进来时（网址带参数）会自动展开，
  否则你根本看不到它识别出了什么。

三、修掉两处「看不见的坑」
  ① 版本号各说各话：Claude 把页面静态版本改成了 v6.7，但服务端还是 v6.6，
     于是标题写 v6.7、右上角徽章显示 v6.6（运行时被服务端覆盖），导出的文件名也跟着写成 v6.6。
     已统一成 v6.7，并加了回归断言，以后两边不一致测试会直接红。
  ② 工作台「工站」映射顺序把 AVI-EB 吃成了 AVI：
     原来是一串 if 从短到长比，`AVI` 排在 `AVI-EB` 前面；
     工站写「AVI-EB」会先命中 `AVI`。已改成规则表按「长 key 先」比，
     顺手补齐了 PRESSURE（原来会落到 CR 或直接漏掉）。

  ★ 另外修了一个真 bug（这条最重要，v6.6 起就有，平时看不出来）：
    「钢网同期分母」那条查面板清单的 SQL 会抽风 —— 同样的语句，
    某些工单参数下要 158 秒，换个参数只要 0.6 秒。实测：
      原样跑两次  158,165ms / 159,562ms
      加 RECOMPILE   607 ~ 636ms
      加 MAXDOP 4    576ms
    根因是参数嗅探：同一条语句被复用到不同工单，缓存的执行计划对这批参数是坏的。
    这条查询纯只读、一天最多跑几次，重编译的成本可以忽略，所以直接钉死
    `OPTION (MAXDOP 4, RECOMPILE)`。修完同一个案例 168 秒 → 15 秒。

════════ v6.6 干一件事：按 SN 追溯拆成两条路 ════════

这一版解决什么：
  你的原话 ——「当前的 BE 追溯 SN 太多的情况下很慢。所以做一个 SMT/BE 联合追溯，
  再放一个单独 BE 段的追溯。」
  实测确认了慢在哪：不是后段慢，是前段取对照板慢。
  后段 100 个 SN 只要 149 毫秒（过站 42ms + 不良 140ms），
  而前段「取前后各 N 个对照 pcs」一个 SN 就要 3~25 秒，5 个 SN 曾经 45.8 秒。
  所以拆开是对的：要查前后段联动就得付这个代价；只想看后段有没有共性，根本不用查前段。

第一件：新增「追溯范围」下拉，两条路二选一。
  · SMT + BE 联合追溯（默认，跟以前一样）：过站 + 对照 pcs + 测量值偏移 + 前后段联动。
  · 仅 BE 段（快）：只查后段过站、后段不良、同工序同期基准。
    不取 SMT 对照板，所以不受 SN 数量影响 —— 实测 1 个 SN 2.2 秒、100 个 SN 2.7 秒。
  选「仅 BE 段」时，「对照 pcs」下拉会自己置灰（这一趟根本不用它），
  下面四个 SMT 侧导出按钮也会置灰并写明原因，只留一个「导出 BE 段 CSV」。
  切模式会清掉上一次另一种模式的结果 —— 免得你拿着旧结果去导出新格式。

第二件：「仅 BE 段」查完给五章结论。
  一、结论：这批 SN 在后段有没有撞在同一台机 / 同一个 holder / 同一个穴位 / 同一条轨道。
     撞了 → 红框，直接说先查那个位置的治具、探针、压头。
     没撞 → 青框，明说「不是后段某一台设备做坏的，往下看前段 SMT 或查测试条件与现场手法」。
     ★ 这里加了一条防呆：如果贴 3 个 SN 只有 1 个在后段查到记录，
       不会拿这 1 块去说「散在不同机台上」，而是明说「这一趟判不了共性，只有 1 块有记录，
       缺的那几个先确认 SN 写法 / 厂区 / 保留期」。样本不够 ≠ 查过了没问题。
  二、每块板走了哪条后段路：一行一个 SN，工序链 + holder + 穴位 + 轨道 + 生产日 + 不良数。
  三、后段不良明细：0 条时明说「不是查询失败，是确实一条都没匹配上」，并给出下一步该干什么。
  四、同工序同期基准：这道工序同期一共过多少块板、这批占多少。
     占比小数太小（比如 1/5,113,326）显示「<0.01%」，不显示「0%」—— 0% 会被读成「一块都没过」。
  五、测试值说明：后段实测曲线不在库里，只给 pass/fail + 工位 + 工装，如实写清。

第三件：联合追溯那条路也快了一倍多（5 个 SN 从 45.8 秒降到 5~8 秒）。
  四处提速，都不改口径，只是让 SQL 和并发更聪明：
  ① 邻居板查询加站别过滤（Ext10='AOI-Rear'/'AOI-Front'），走三列复合索引，单条从 3.6 秒到 1.6 秒；
  ② 前后两个方向、pcs 的两段查询全部改成并行；
  ③ 同一「产品|机台」组共享一次邻居搜索 —— 100 个真实 BE 不良 SN 按这组分只落 16 组，
     逐 SN 各查一遍等于把同一条 SQL 跑 16 次；
  ④ 窗口逐级放大时加短路：前两个窗口一条都没查到就跳兜底，不再白跑后面三档；
     兜底（去掉站别过滤那次慢查询）只在「一条都没查到」时才发。
  ClickHouse 侧也并行化了（SPI 逐板串行曾独占 10.6 秒），并把扫描窗的日期余量
  从 3 天收到 6 小时 —— 实测目标板 AOI 从 2.3 秒降到 1.3 秒。

第四件：新加 58 项回归测试（tests/v2_beonly_test.js）。
  除了功能，专门守住几条容易被后人改回去的口径：
  · 仅 BE 段这条路不许出现 neighbors / chAoi / chSpi（一出现就不叫「快」了）；
  · 后段基准 SQL 不许写 COUNT(DISTINCT PanelCode)（实测加 DISTINCT 从 2.6 秒变 137 秒）；
  · 「这批走过几块」和「全厂同期几块」是两个字段，不许混用；
  · 取不到基准时给 null 不给 0（「没基准」和「0 块」是两件事）。

第四件：顺带修了四个真 bug（都在导出/口径上，不是观感问题）。
  ①「导出明细」的 AOI 行少写一列（表头 18 列、AOI 行只有 17 个值），
    导致 OffsetX / OffsetY / Rotation 在 Excel 里整体右移一格 —— 现在 12,600 行全部 18 列对齐。
  ② SPI 测量值全被丢掉（0 行）：SPI 表里存的是板号基码（PANEL00001），
    不是 pcs 条码，拿 SN 去比必然全掉 —— 现在按「板号基码 + 穴位」认，回来 85 行。
  ③ 空字符串的测量值被写成 0：Number('') === 0，于是出现「实测 0.00 / 规格 0~0 / 不超规」，
    比空着更误导 —— 现在空值一律当「没测」，整行跳过。
  ④ 测试值对照在 pcs 口径下会空表：原来靠 loc|modid 认基准，而每块 pcs 只有一个模组号，
    目标和对照永远对不上 —— 现在 pcs 模式下改用 loc 当基准键，稳定出 80 行。

关于后段 BE 的「测试值」，如实交代一句边界：
  后段测试（VSWR / 灵敏度等）的实测曲线不在数据库里，只存在文件共享的 txt 里
  （表里存了路径，但本机访问该共享被拒绝），所以 BE 侧只能给 pass/fail + 工位 + 工装 + 起止时间。
  这不是漏了，是取不到 —— 全链路表的说明里也会写这一句。

v6.4 干四件事：
第一件：前段 SMT 也有「时间段不良分布」了，而且会判「有没有突然上升」。
  以前只有后段 BE 有这个图，前段只能看按天的条数，判断「是不是突然起来的」全靠眼睛。
  现在两段一致：上面一根按天的柱，下面 24 根按小时的柱，再加一句判定。
  判定口径（先说清楚，免得误会）：
    · 把按天的条数切成前 1/3 和后 1/3，比较两段的平均值；
    · 后段 ≥ 前段 2 倍 → 判「在上升」；1.3~2 倍 → 「略有抬头」；低于 → 「平」或「在下降」；
    · 单天 ≥ 窗口内中位 3 倍 → 单独标成「孤立尖峰」（红柱），
      注意：孤立尖峰不等于「整体在上升」，这两件事工具分开说，不会混在一起骗人。
    · 样本不足（总数不到 8 条，或不足 4 天）→ 直接写「看不出来」，不硬给结论。
  为什么不用回归斜率：不良条数是离散计数、常有 0 值，一个 200 条的尖峰就能把斜率带偏，
  让工具说出「整体在恶化」这种假话。三段均值抗噪，也和你在一线看板上的判断方式一致。
  同时修了一个藏了很久的真 bug：MES 的 CreateTime 取回来是 Date 对象，
  以前用 String(...).slice(0,10) 取日期，得到的是 "Mon Oct 19" 这种，和 "2026-10-19" 对不上，
  导致「这波是慢性还是突发」那张图里「本次分析窗」的深色柱一根都画不出来过。
  现在统一走 mesDayOf()，实测窗口 10-19~10-25 的 4 天全部正确命中（修复前 0 天）。

第二件：等待的时候弹一层动画，顶上有司南的图标。
  以前点「开始分析」之后，页面只是静静地转，数据量大时要等十几秒，
  很容易以为卡死了、然后去重复点按钮。现在会弹一层：
  司南图标在左上转 + 大号百分比 + 进度条 + 一行「现在在干什么」的人话字幕
  （取数 / 定位不良 / 算暴露量 / 显著性检验 / 分离被动共现 / 出结论）+ 一句解释。
  百分比到 92% 就停住等真实结果，不会在没算完的时候显示 100% 骗你。

第三件：打包发给同事的压缩包里，账号密码已经配好了，双击就能用。
  以前同事拿到包要自己填数据库地址账号密码，不会填就用不了。
  现在包里有 config/ 文件夹，装好了公司内网的只读账号，
  双击「启动工具」直接能查，不用再填一遍。
  想换成自己的账号也不用改包里：在你电脑上建 ~/.config/sinan/mes.local.json 就会盖掉它。
  另外这一版把「给MES的说明_资源使用与申请.txt」和「搭建逻辑与协作指南.html」从包里拿掉了
  ——这两份是给内部对接用的，同事日常用不上，留在包里只会增加困惑。

第四件：另出了一份 3 页的工具介绍，最后一页留了我的联系方式。
  那份是给要分享给别人的时候用的，标题叫「司南能帮你做什么」。
  里面回答三个问题：它能干什么 / 我可以用它做什么 / 有事找谁。
v6.3 干两件事：①「被动共现分离」——你举的例子是载具 90 号穴位有异物，穴位维度集中、同批材料跟着集中、
  贴 90 号穴位的吸嘴和轨道也显得集中，但吸嘴和轨道本身没问题。做法是对每个已上榜的显著项，把别的项整条剔掉
  （暴露一起减）再按新基准率重算倍数：剔完仍 ≥1.5× → 它有独立问题；剔完掉到 1.5× 以下、且对方剔完仍高、
  且 ≥50% 不良重叠 → 判「被动共现」并点名是谁拖的；两项不良板几乎完全重叠且倍数差 ≤3 倍 → 判「同簇」
  （同一条线索的不同视角，不硬拆成根因+被动）；倍数差 >3 倍不许并簇，防止 233× 的穴位和 1.9× 的机台被说成一件事。
  实测 PRODUCT-A-005 / C0201：12 个信号里 3 项被动（三个材料批号被穴位 139 解释，剔后一条不良都不剩）、3 组同簇。
  这一层只回答「A 的集中能不能被 B 解释」，不是因果证明，要坐实还得靠换件复测。
  后段 BE 有意不做这层——机台/holder/穴位/轨道同源解析、天生嵌套，剔除必然造假被动。
  ② 等待浮层：大号百分比 + 进度条 + 阶段字幕 + 人话提示，92% 停住等真实完成，算完让 100% 停 0.4 秒再收。
v6.2 只干一件事：回答「工序有先后，前段置件问题会不会让后面的工站都显得高」这个问题。
变化只有一个地方——后段（成品测试）的结论多了一层「首因 / 传导」判读，SMT 段完全没动。
以前后段告诉你「AVI 的 LINE-C 这台机不良多 3.5 倍」，你会去查那台测试机；现在会多一句：
这批板里 99.6% 是在这道工序第一次被判 NG，还是说大部分在前站就已经 NG 过、AVI 只是把它照出来了。
判读分三档：首因率 ≥90% 写「首因（源头在本工序）」；≤50% 写「疑似传导（先查前站 X）」；
中间写「首因/传导各半（两条都要查）」。首因率低的那一项会自动从「显著信号」降级到
「看着集中但不能直接当结论的」表里，不会让你拿着错误的结论去开检讨会。
实测结论：后段内部跨工序传导极少（AVI 99.61%、VSWR 99.69%，都在 0.4% 以下），
所以「前段问题导致后面工站都高」这件事基本不发生在 BE 内部——
它发生在 SMT → BE 这条边上，所以在「前后段联动」那张表里加了「传导链判读」一段话，直接告诉你
SMT 侧找到的那几条（飞达 / 吸嘴 / 载具）就是首因，后段属于被动共现，别去改测试站。
另外顺手把导出报告补齐：结论报告里新增「首因判读」一章，显著信号表和「没通过检验」表都多了
「首因率」和「判读」两列，跟页面完全一致。
v6.1 是按 codex 审核规格书改的四件事，全是「数字可信度」问题，界面基本没动：
① 日期口径统一到本地时区（Asia/Shanghai）——原来服务器给的是 UTC，跨零点的那一小时会被算到前一天，日均、周几、小时分布都跟着偏；现在全部走本地日历日，并补了时区回归测试。
② 「日均」按实际分析窗口算、空白日期计 0——原来分母只数有数据的天数，项目放假/停线那段会让日均虚高；现在窗口几天就除以几天，没数据的那天算 0 条。
③ 300 条抽样改成「按不良 ID 的 MD5 稳定哈希」——原来取最近 300 条，等于让时间越近的不良越容易被看到，结论会随时间漂；现在同一份数据重跑永远抽到同一批，报告可复核，而且页面、结论报告、导出 CSV 三处都写明「哪些数字是全量、哪些是抽样」。
④ 多重检验改成「跨维度 Holm 校正」，并把「分散」的措辞改硬——原来每个维度内部各校一次，13 个维度等于开了 13 次小灶，假阳性偏高；现在把全部维度的全部候选合成一个检验家族一次校正（本次实测一次分析 59 个候选），达不到就明确写「本批未发现通过门槛的显著集中，不等于已经排除」，不再出现「可以排除」这种话。
另外两件顺手做的：并发说明写清是「本机限流」（本机最多 2 个分析，多人共用要装部门共享服务才有全局排队）；数据库账号密码从源码里拿掉了，改成第一次双击「首次配置_数据库连接」填一次、存在你自己的电脑里（~/.config/sinan/），以后不用再填。v6.0 七道防护（31 天上限、并发闸门、DOP 4、NOLOCK、连接名、人话报错、索引化保留期探测）全部保留。
v5.2 四件事：①按 SN 查的共性口径重做——后段只看机台/holder/穴位/轨道/生产时间，前段补上轨道、材料料号、材料厂商，不再拿「工序/不良现象/产品」这些已知信息当共性，并且区分「全部相同」和「都走过但各自还有别的」两种说法；②查不到测量值/导出空表时，界面直接写清原因（ClickHouse 只覆盖部分项目），并修掉「只查 TS_AOI_Rear 导致对照板恒为 0 块」的真 bug；③后段（成品测试）和 SMT 前段终于打通了——后段判 NG 的板会自动回查它在 SMT 是哪台贴片机、哪个吸嘴、哪个飞达、哪个载具做的，并给出倍数和显著性；④后段产品下拉后面补上了机型名（LINE-A / LINE-D 这种），不用再背产品码；v4.9 三件事：①筛选顺序改成「项目 → 日期 → 工站」，工站后面直接跟这个窗口的不良数、按数量从高到低，选完上一层下一层自动收敛；②新增「意见反馈」按钮，里面就是我的邮箱和电话，还能一键复制当前筛选条件；③导出的不良明细 CSV 顶部会多一段「工站 Input / Output / 良率」汇总；v4.8 增加明细保留期提示：MES 的 AOI 主表只留约 25 天，选到被清理的日期会明确告警而不是空白；v4.7 按 SN 全链路追溯 + 后段 BE 接入：AVI/AVI-EB/CR/ICT/LEAKAGE/PRESSURE/SENSITIVITY/VSWR 八道工序 + 按 SN 查；v4.5 样件/试印板剔除全覆盖；v4.1 改名司南 SINAN）

第 1 步 选条件（上半部分）
  · 段别：下拉里分三组 ——

  ★ 选了 BE 那一组，界面会自动切到后段模式（这是 v4.7 的新东西）：
    · 时间只到「天」，小时和基准天数会变灰 —— BE 按整天取数
    · 结束日期默认挪到「昨天」：当天的过站记录还在陆续回填，拿今天当结束日
      会让分母偏小，算出「不良率 585%」这种不可能的数
    · 「不良点位」变成「工位（可选）」，选的是工位码（如 `<工序前缀>AVI0001-09`）
    · 多出一排「不良点位（后段）」chips，来源是 ECodeMemo 里的板上点位
      （COMP-A、PSA1、7_0_FPC 这类），可多选
    · 「扩样验证」和「测量值分布」两个按钮会灰掉 —— 这两样只对 SMT 段有意义
  · 开始/结束日期 + 小时：精确到「几号的几点」。
    例如 10/09 08 点 → 10/10 12 点，就只算这一段时间的不良（不需要算整天）。
    ⚠️ 算当前这一小时时，数据可能还没落完，建议至少隔 1 小时再跑
  · 项目 / 产品：选具体机种就不会把别的项目混进来
  · 工站 / 机台：想只查某台机就选它
  · 不良点位：必选。不选它就没有贴装/吸嘴数据
  · 不良现象：点一下就选中，可多选；不选 = 全部现象
  · 跨工单载具回看：近 7/14/30 天（默认 14 天），给「载具·跨工单」用
  · 【排除待复判】默认勾上 —— 「待复判」是还没复判的记录，不是真不良，
    混进来会把结论带偏（实测：勾上 31 条 → 分散；不勾 49 条 → 假信号）

★ 项目有 300 多个，用右上角那个「输入关键字筛选」框直接打字：
  输入 J181 → 只剩 1 个；输入 UAT2 → 剩 97 个（产品名也能匹配）。

  显示「无匹配项目」就是真没有，换个关键字即可（区分大小写？不区分）。

★ 筛选是级联的：选了上一层，下一层只剩能对上它的选项，
  每个选项后面的数字 = 在当前条件下有多少条不良。例如：
    选点位 COMP-A → 机台只剩 LINE-A 一个（自动选中）
    选了机台 → 点位的数字跟着变

第 2 步 点「先看有多少条不良」

    三、慢性 / 突发判定（本窗日均 vs 历史基准，变好绿、变差红加粗）

    六、同一把吸嘴/飞达跨机台
    七、载具跨工单
    八、指标区分度（AOI / SPI 哪个指标最能分开 NG 和 OK）
    九、扩样验证结果（做过才有）

    · 绿色 = 正常品（散点 2500 个 + 浅绿密度轮廓 + 箱线：P5/P25/中位/P75/P95）
    · 红色 = NG（全部点 + 小箱线）
    · 橙色虚线 = LSL / USL（规格线怎么来的见下面「画法」一节）
    ★ 已剔除试印板（SY）和样件（Sample），图注里会写出来
  默认按 AOI、当前点位、本批占比最高的不良现象自动跑一次。
  ★ 不需要再选数据源/元件/指标：它自动用你现在选的点位、时间窗和现象，
    AOI 和 SPI 的指标一起扫，挑分得最开的那个直接画出来。
  图上排是第一行是各指标的区分度（NG 落在 OK 的 P1~P99 之外的占比），点一下切换。

  五个指标（OffsetX / OffsetY / Rotation / Lift / Height）**一次性并排画出来**，
  不用一个个点。按区分度从高到低排，第一张就是最值得看的。
  右上角有「AOI 深度分析（原工具）」，点开就是 MK ver1.49 那个工具，可以拿同一批数据做更深的分析。

  画法（沿用 AOI 深度分析 v1.51 的判读逻辑）：
    · 小提琴轮廓 = 密度（KDE，Silverman 带宽），宽 = 该数值附近的样本多
    · 中间白盒 = 箱线（Q1/中位数/Q3，须线 1.5 IQR，空心圈是离群点）
    · 点 = 真实测量值，按密度横向铺开
    · 两组共用一条 Y 轴，可以直接比高低
    · 橙色虚线 = LSL / USL，数值自动从数据里取（取中位数）
      OffsetX / OffsetY / Rotation 是双向规格：只有一侧时自动补另一侧的负值（如 USL 5 → LSL -5）
      Height / Lift 是单向规格，只画上限，不补负值
      坐标轴会自动把规格线包进来，保证上下限线一定看得见
      每张小图下面有 LSL / USL 输入框：改完回车即生效，会记在本机；
      点「自动」恢复成数据里的规格值
    · 五张小图一次画全（OffsetX / OffsetY / Rotation / Lift / Height），
      按区分度从高到低排，第一张最值得看
  SPI 数据源用的是「元件_穴位」命名，SPI 的指标是 Volume/Area/Height/Offset 三组
  （% / mm 各一套），规格线取表里的 *_LSL/*_USL，没有就按 Standard(mm) × 百分比推算。

第 4 步 看结果（从上往下）
  ① 结论卡：一句话告诉你是"有共性"还是"分散"
  ② 为什么还不能下结论：混杂提示（比如吸嘴和机台分不开）
  ③ 通过了显著性检验的信号：真正的信号，点一行能下钻到单板
  ④ 各维度分布：机台/吸嘴/飞达/料台/穴位/载具/线体/SPI/材料

      · 同一把吸嘴两台机都差     → 才是吸嘴自己的问题

  ⑦ 下一步怎么验证：给 PE/EE 的具体动作
  ⑧ 不良单板明细：可导出 CSV

────────────────────────────────────────
三、口径（这几个数字怎么算的）
────────────────────────────────────────
· 暴露（分母）：同一块板、同一位号、其余 89 个穴位的贴装
  —— 同一批板自己当对照，不用抽样，最干净。
· 风险比 lift = 该取值不良占比 ÷ 该取值暴露占比
  1.0 = 跟平均一样；2.0 = 是平均的 2 倍。
· 显著性：二项上尾检验 + Bonferroni 校正（α=0.05）
  ★ 为什么要校正：90 个穴位、59 个批号里，总会几个"碰巧"
    凑出 3 条不良。不校正就会把噪音当结论。
· 载具/线体：分母用「前 N 天 · 同线体 · 同工单」的 3000 块板。
  ⚠️ 载具（同工单基准）这张卡里 1/1、2/2 那种 8 倍、10 倍是**单板噪音**，
     暴露不足 10 块的载具一律不进结论榜，别拿它去开会。
· 时间窗精确到小时：SQL 用 CreateTime >= 开始 且 < 结束（结束那一小时算到 59:59）；
  基准天数、跨工单回看仍然按「天」算，从结束日期往前推。
· 单次分析上限：**1000 条不良**（v6.7 起从 300 提到 1000）。超过时按不良 ID 的 MD5 稳定哈希抽 1000 条进入分析（不是「最近」那批），页面和报告顶部会写明「总体 N 条 / 分析 1000 条 / 占比 P%」。
  为什么要限：实测 854 条不良 / 789 块板时，取数要 146 秒，浏览器等不到就会报
  「Load failed」（这是网络层断开，不是工具算错）。要全部结论就缩时间窗或加筛选。
· 跨工单载具最多回看 120 个载具（再多要去查 5 万块板，太重）。
· 基准兜底：扩样跨了多个工单时，「前 N 天」可能还没开工 → 自动改用「分析窗同期」，
  并在结果里标注「基准改用了同期」。
· 扩样验证：只改开始日期（往前 7 天），其他条件一律不动；两窗口各自独立计算，
  逐项比对「原窗口判定 → 扩样后判定」，不共享中间结果，避免自己跟自己对不上。
· 吸嘴/飞达跨机台：同一批板里，同一把吸嘴在每台机上的「不良数/暴露数」直接对比，
  用两比例 z 检验 + Bonferroni 校正；样本 <20 的一侧不参与判定。
· 载具·跨工单：分母 = 这批不良板用到的载具，在近 N 天里跑过的**所有板**（不限工单）；
  分子 = 其中同机台同点位同现象被判 NG 的板。
  ★ 注意它的口径是「近 N 天」，不是「这一批」——所以它的不良条数会比本批多，
    这是正常的，看的是长期表现。

6. BE 段的「分母」是过站记录，不是不良表 —— 因为不良表里 PASS 行覆盖率太低
   （1 小时窗：不良表 314 行 vs 过站表 53,408 行），拿不良表当分母会虚高几百倍。
   所以：不良来自 T_Bllb_TestDefectInformation（IResult=0），
        分母来自 TRS_Busi_StationTrace 同工序的过站板数。
7. 过站记录会滞后回填：实测有产线的 10-20 过站只写了 34 行，那天的 199 块不良板
   的过站行是 10-21 才补进去的。工具会自动把「不良数 > 过站数」的取值从显著榜剔除，
   并在「为什么还不能直接下结论」里点名提醒 —— 看到这条就说明要换天再跑。
   所以 BE 的结束日期默认放在昨天，别拿今天跑。
8. BE 的「工位」维度只给谁出得多，不折算倍数：过站表和不良表的工位码写法不完全一致
   （一部分产线按机台记，如 `<机台>AVI0013`；一部分按工位记，如 `<机台>AVI0004-14`），
   实测同一工位码在两张表里的板号交集是 0 条，算倍数没有意义。定机台请看「机台」维。
9. BE 一次只查一道工序（AVI/VSWR/ICT…各查各的），因为 8 道一起 join 要 120 秒超时。
10. 后段一台机器测的「穴位」概念和 SMT 不同，BE 没有「穴位×现象」这种分析。
11. 按 SN 查（客诉反查）：顶栏那个按钮。贴一批 SN，工具会同时拉四路：
   · SMT 全程过站（含载具、钢网、工单、机台）
   · SMT 的 AOI / SPI 结果，以及 ClickHouse 里的实测值（OffsetX/Y/Rotation/Lift/Height）
   · BE 全程过站与不良（走另一个库 <BE_HOST>）
   · 这块板前后各 200 块「同产品 + 同机台」的正常板，用来做对照
   输出三块：① 每块板走了哪条路 ② 跨 N 个 SN 的共性（18 个维度，≥2 个同值才列）
   ③ 测试值偏移（这板实测 vs 正常板 P5~P95，>2 IQR 算偏离、超出 P5~P95 算出界）。
   三个导出：明细 CSV / 过站汇总 CSV（带 SN 列 + 「角色」列）/ 测试值对照 CSV。
   一般 7~25 秒。贴的 SN 多会均分那 200 块对照板（每块板都还够用）。
   若某个 SN 查不到：确认板号写法（后段 ProBar / 前段面板码都认）以及是否在保留期内。

   ★ 共性维度（v6.0 重做，按用户要求「看设备/轨道/载具/吸嘴 + 生产时间，
     不要工序/不良现象/产品，那些是已知信息」）：
     后段：测试机台、工位（holder）、穴位、轨道、工序、生产日
     前段：载具、轨道、穴位、贴装机台、贴装吸嘴、飞达、材料料号、材料厂商、材料批次、生产日、工单
     检测：AOI 判 NG 点位、SPI 工站
   ★ 三种判定的区别（以前一律写「全部相同」，是错的，v6.0 改掉）：
     · 「全部相同」= 每块板都只有一个取值，且彼此完全一样（例：都是 LINE-B）
     · 「都走过 X（每块板还走过别的）」= 每块板都有 X，但每块板还有别的取值
       （例：穴位都走过 01，但两块板各自还走过 04/08）—— 这是弱信号，别当结论
     · 「没有 2 个以上 SN 共用」= 分散，真的没关系
   ★ 前段的「轨道」在明细里会标「按工序固定」：实测 Mount-1 恒为 1、
     Reflow 恒为 2、SMTVI 恒为 0，每块板都一样，所以它不参与结论，只供查看。

   ★★ 为什么「导出明细」「测试值对照」有时是空表（v6.0 查清并写进界面）
     ClickHouse 的 AOI 明细只覆盖一部分项目/机台，不是所有板都会进。
     实测（2026-10-26）：10-23 这天 1.14 亿行里，J181A01/J183B01/J189A01/L621A01 有，
     J183C01/J180C01/J187C01 一块都没有 —— 而这两块被查的板正是 J183C01 开头。
     所以：
       · 查了 N 块目标板 → 页面顶部直接写「ClickHouse 里一块都没有 / 只有几块有」

     另外 v6.0 修了一个真 bug：取对照板时原来只查 TS_AOI_Rear，
     但这个产品（PRODUCT-A-006 / LINE-B）的 AOI 全在 TS_AOI_Front
     （Rear 0 行、Front 226 万行），于是对照板永远是 0 块、测量值对照永远空。

★★ v4.9 三个新东西
14. 筛选顺序变了：现在是 ①项目/产品 → ②开始日期 → ③结束日期 → ④工站 → ⑤机台 → 不良点位。
    为什么这么改：实际排查是先定「哪个项目出问题」，再看「哪几天」，然后才关心「哪道工站」。
   · 工站下拉后面直接跟数字，是这个窗口内的不良数（例：AOI-Rear · 6950），
     按不良数从高到低排；没有不良的工站不会出现，免得选完发现是空的。
   · 每选完上一层，下一层自动收敛：选了项目 → 工站只剩这个项目有不良的；
     选了工站 → 机台只剩这个工站有不良的。工站上方的「（N 个有不良，按数量排）」
     就是这个窗口里还剩几个工站可选。
   · 数字走单独一条轻查询（1 天约 0.2 秒、7 天约 0.6 秒），不会拖慢主分析。
   · 后段（BE）的工序也会带数量（例：成品目视 AVI · 80201），但为了不卡，
     只在窗口 ≤10 天时才查。
15. 右上角「意见反馈」按钮：点开就是维护者的邮箱和电话，可以点「复制邮箱」「复制电话」，
    （这两项由 config/contact.local.json 或 SINAN_CONTACT_MAIL / SINAN_CONTACT_TEL 提供，
     源码里不预置 —— 没有配置时显示「这一份没有预置维护者联系方式」）
    另有「复制当前条件」——会把你此刻选的版本/段别/时段/项目/机台一起带上，
    发消息时贴过来，我一眼就知道你说的是哪一次分析。
16. 导出明细 CSV 顶部多了 Input / Output：
   · Input = 这个工站这个时段「过站检验次数」（TRS_Busi_StationTrace 的 PCBCount 合计）
   · Output = 判 OK 的次数（OkCount 合计）
   · 不良数 = Input − Output，良率 = Output / Input
   · 注意：下面明细一行是「一个点位的一次不良」，一块板有多个点位就会多行，
     所以明细行数通常大于 Input−Output；CSV 里也写明了这句，别拿行数直接对。
   · 只选了段别（工站）才有这段；后段 BE 的导出走它自己那套表头。

★★ v6.0 两个新东西（后段和 SMT 打通了）
17. ★★ 后段（BE）和 SMT 打通了（v6.0 最重要的一条）
   以前：后段成品测试（AVI/VSWR/ICT…）判了 NG，你只知道这块板在后段哪道工序坏了，
         不知道它在 SMT 是谁贴的——只能拿板号去「按 SN 查」一个个翻。
   现在：后段分析出结果后，页面下面会自动多出一张表「前后段联动：这些后段不良板
         在前段 SMT 是什么做的」，一行一个维度，列分别是：
           维度 / 取值 / 不良板 / 不良组占比 / 对照板 / 对照组占比 / 倍数 / 校正后 p
   · 倍数 = 不良组里这块板占比 ÷ 对照组里占比。★ = 显著（校正后 p<0.05 且倍数≥1.5
     且不良板≥3 块）；★ 行是浅红底 + 红字 + 倍数红色加粗，一眼能挑出来。
   · 对照板 = 「同一时间窗、同一道后段工序判 OK 的板」（例：这批是 AVI 判 NG，
     对照就是这几天 AVI 判 OK 的板）。它们过站路径和不良组一样，只是没被判 NG，
     所以比的是「走过同一个地方的比例」，不是「不同机型之间瞎比」。
     （这条口径 v6.0 推翻重做过两次：①早先按产品模糊取，两组机型对不上；
       ②改成「同工单取前段面板」，取到的是整条流程走满的板，会算出 111 倍这种假值。）
   · 会看 8 个维度：前段工序（Process）、前段工站（Station）、贴片机、载具、钢网、
     吸嘴、飞达、穴位。其中「前段工序 / 工站」这两档就是过站集中度——
     不良组有多少块板走过这道工序 / 这个工站，对照组又有多少块，倍数 = 前者 ÷ 后者。
     （v6.0 删掉了原来的「前段 AOI 不良现象 / 点位」两维：那是 AOI 自己判的结果，
       不是过站集中度，放进这张表只会把真信号挤下去。）
   · 一条线上的板会依次走过该线所有工站，所以好几个工站的板集合往往完全一样。
     工具会把这类「走过同一批板」的站合并成一行，后面标「等 N 个站/工序走过同一批板」，
     不会连着刷五行一样的数字。
   · 怎么看：飞达/吸嘴/载具有 ★ → 直接去现场查那个物料；贴片机有 ★ → 集中在一台机，
     查那台机的程序/供料器/模组；穴位有 ★ → 集中在大板某个位置，一般和托盘/治具相关。
   · 「对照板」不足 30 块时页面会黄字提醒「当线索看，不要当结论」。
     想把结论做实，把时间窗放大到 3~7 天再跑一次（v6.0 已提速：1 天约 3~5 秒、7 天约 5~7 秒）。
   · 导出结论报告时这张表会自动进去，不用另外导。
   · 实测样例（2026-10-22 AVI 一天）：400 个后段不良板号 → 在前段对上 121 块拼板；
     对照板（同窗 AVI 判 OK）300 块；抓出
     「飞达 FEEDER0001 13/121 板（16.5%）vs 对照 8/300 板（4.1%），3.89 倍，p=0.012」、
     「吸嘴 00001 19/121 板（15.7%）vs 对照 14/300 板（4.7%），3.36 倍，p<0.001」、
     「贴片机 LINE-A 35/121 板（28.9%）vs 对照 39/300 板（13.0%），2.23 倍，p<0.001」、
     「前段工站 D04-3F-05ST3-Panel-to-tray 23/121 vs 25/300，2.28 倍」等显著项。全程 4.3 秒。

18. 后段产品下拉带机型名（v5.2）
